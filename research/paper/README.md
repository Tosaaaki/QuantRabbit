# paper — 仮想トレードと戦略追加

戦略を増やすための場所。**増やすこと自体は簡単で、難しいのは採用してよいか決めること**なので、
このエンジンは最初から `QR_AI_STRATEGY_ALLOCATION_V1`（`docs/AGENT_CONTRACT.md` §2）の
合格条件をそのまま吐く形で書いてある。

**ライブには一切触らない。** 参照するのはリプレイコーパスのみ、書くのは JSONL 1本のみ。
ブローカー・注文経路・ライブ権限に接続しない。台帳の各行は `"paper": true` /
`"live_permission": false` を持つ。

## 使い方

```bash
cd research/paper
python3 engine.py                          # 全戦略 × 4ペア、TRAIN/TEST 分割レポート
python3 engine.py USD_JPY EUR_USD          # ペア指定
python3 ledger.py --since 2026-01-01       # 前向き台帳へ追記（冪等）
python3 ledger.py --scorecard              # 貯まった台帳に合格条件を当てる
```

## 戦略を1本足す手順

`strategies.py` に関数を1つ足して `@strategy("名前")` を付けるだけ。
`f` は因果的な特徴量の辞書、返り値は `+1` / `-1` / `None`。**バー `i` より後を見てはいけない。**

```python
@strategy("my_idea")
def my_idea(f, i):
    if f["z20"][i] < -3.0 and f["eff"][i] < 0.1:
        return +1
```

足した戦略は他と同じ執行モデル・同じ合格条件で採点される。
**物語では採用されない。**

## 執行モデル（全戦略共通・変更するなら全戦略同時に）

- エントリーはシグナル足の M1 終値、スプレッド半値を支払う
- 8時間後の終値でイグジット、再びスプレッド半値を支払う
- 災害SL 50 pips。ストップ価格は固定なので、前方 min/max のローリングで**厳密に**判定できる
- 同一戦略・同一ペアで同時に1玉（クールダウン = 保有時間）。同じシグナルの積み増しで日次を膨らませない
- TP なし（SL-free / TP-free の家の方針）

**結果は pips のまま。** JPY 換算にはバーごとのクォート通貨レートが要るが、
このコーパスは USD 建てペアのぶんを持っていない。適当なレートを置くのは、
前セッションの欠陥#4（円換算漏れ）と同じ穴なので、やらない。

## 負けの分解 — シグナルかコストか（2026-08-05）

「合格0/52」で止めず、**なぜ負けるのか**を分解した（`cost_decomposition.py`）。
同一エントリーでスプレッドを課さない GROSS と、課した NET を並べる。

保有240/480分では **24候補中12がGROSSプラス**。最良 `mtf_aligned_pullback@480` は
GROSS **+0.577** pips/取引に対しコスト 1.378 → NET -0.801。
**シグナルには符号がある。負けているのは執行コスト。**

さらに引き継ぎ書 §2.1 が「**コーパスのスプレッド1.70は実測0.80の2倍以上**」と確定させており、
**このエンジンは真のコストの約2倍を課していた**。実効0.80に直すと不足は **0.22 pips/取引**まで縮む。

## 多戦略は補い合うか（`portfolio.py`）

**補い合いは平均を作らない。** `E[和] = 和[E]` なので、負の期待値を束ねても負のまま。
束ねて効くのは**分散**＝配分ゲートが見る下限のほう。それを踏まえて実測した:

- TRAINの日次平均がプラスの20本を等ウェイトで束ねる（**TESTは見ずに選ぶ**）
- **TRAIN +1.76 pips/日 → TEST -2.18 pips/日、下限 -5.53、勝ち日38%。不合格**
- 日次リターンの相関は **0.2〜0.7** — 長保有トレンド/ブレイク系ばかりで**独立していない**
- 例外は `fade_range` / `fade_stretch` で他と **相関 0.0〜0.15**。
  **本当に補い合うのはこの2本だけ**だが、単体が弱い

**結論**: 「多戦略で補い合う」は、①各戦略の期待値が正であること ②互いに独立であること
の両方が要る。現状はどちらも満たしていない。**先に必要なのは戦略の本数ではなく、
1本あたりのコスト**。

## 「多戦略で少しずつ確実に取れば3倍」を数字にした（`target_frontier.py`）

直感は方向として正しいが、**証拠金は共有**なので本数は素直には効かない。

N本を同時に建てると1本あたりの元本は 1/N。日次リターンは pips の **平均**で決まり、
本数は式から消える。本数が効くのは **(1) 回転**（保有が短ければ同じ証拠金を1日に何度も使う）
と **(2) 分散**（独立なら下限が上がって「確実に」が成立する）の2経路だけで、
**分散は平均を上げない**。積み上がるのは本数ではなく回転。

必要条件: `1取引あたりの純益(pips) × 1日の回転数 × 全証拠金での1pip価値 >= 目標日次JPY`

### NAV 20万・レバ25倍（全力時 1pip = 318 JPY）

| 月倍率 | 日次% | 必要日次pips | 1回転 | 3回転 | 6回転 | 12回転 |
|---|---|---|---|---|---|---|
| 1.5x | 1.95% | 12.2 | 12.24 | 4.08 | 2.04 | 1.02 |
| 2.0x | 3.36% | 21.1 | 21.07 | 7.02 | 3.51 | 1.76 |
| **3.0x** | **5.37%** | **33.7** | 33.73 | 11.24 | 5.62 | **2.81** |
| 4.0x | 6.82% | 42.9 | 42.86 | 14.29 | 7.14 | 3.57 |

### 実測候補はどこに立っているか

| 候補 | net/取引 | 取引/日 | 日次pips | 全力時 日次% | 月倍率 |
|---|---|---|---|---|---|
| mom_break@2880 | 3.278 | 2.13 | 6.98 | 1.11% | **1.26x** |
| vol_squeeze_break@2880 | 1.527 | 1.58 | 2.41 | 0.38% | 1.08x |
| vol_expansion@960 | 0.293 | 3.77 | 1.11 | 0.18% | 1.04x |

**`mom_break@2880` は 1取引 3.278 pips を稼いでいる。3倍に必要な「12回転で2.81 pips」を
1取引あたりでは既に超えている。足りないのは回転（2.13回/日）。**

### ここが律速 — 回転を上げるとコストが線形に増える

| 回転/日 | 摩擦 pips/日 | 摩擦 %/日 | 3倍に必要な素の pips/取引 |
|---|---|---|---|
| 3 | 2.4 | 0.38% | 12.04 |
| 6 | 4.8 | 0.76% | 6.42 |
| **12** | **9.6** | **1.53%** | **3.61** |
| 24 | 19.2 | 3.06% | 2.21 |

**回転12回/日なら、何もしなくても 1.53%/日 が摩擦で消える。**
受動指値で入口の半スプレッドが消えれば摩擦は半分になる。
**高回転にするほどスプレッドが律速。だから受動指値の実証が3倍への必須経路。**

**ただし上の候補は out-of-sample を通っていない**（`portfolio_long.py` で
TRAIN +1.76 → TEST -2.18、下限 -5.53）。月倍率は「もし本物なら」の上限であって期待値ではない。

## 次の一手 — S5で受動指値を測る

残っているレバーは執行コスト。GROSS +0.577 に対しコスト 0.80 で、差は 0.22。
**受動指値で入れば入口の半スプレッドが消え、複数候補が黒に転じる。**

**「S5では22/22全敗」の読み方（2026-08-05 訂正）**: 生成元 `run_pairscreen_s5.sh` が試したのは
`range_fade_limit`(tp=6, SLなし) と `spike_fade`(tp=3.0ATR, SLなし) の**逆張り2ジオメトリだけ**。
**11ペア × 2窓 = 22テストであって22戦略ではない。** 1つの発想を22回測っただけで、
**S5でモメンタムは一度も試されていない**。「S5では何をやっても負ける」は確立していない。

ただし **M1リプレイでは絶対に測ってはいけない**（§2.2 欠陥#1: M1で受動指値を仮定して
11ペア全勝→S5で22/22全敗）。正しい道具は既にある —— **S5コーパス
（`oanda_history_s5_2024_2026`、11ペア×2年、8,378万行）**。
これが前セッションが作った最大の資産で、この目的のために作られている。

  バー `i` 自身が自分の前方窓を汚染し、災害SL判定が甘くなる。
  ブルートフォース一致テストを消さないこと
- 累積 pips と日次下限は別物。**下限を見ずに採用しない**
- TEST を見て戦略を選べば、TEST は TRAIN になる。
  採用前に `ledger.py` で未見の日を貯めて再確認する
